# fermix-plugins

Source home for [Fermix](https://github.com/tezra-io/fermix) plugins.

Plugins live here — not in the fermix repo — because they are self-contained
integrations that may be written in **any language** (declarative JSON, Node,
Go, Python, …). Keeping them out of the Elixir umbrella keeps foreign
toolchains out of fermix's build and lets each plugin version and release
independently.

## How distribution works

1. **Source** — one directory per plugin under [`plugins/`](plugins/) (see
   [`plugins/README.md`](plugins/README.md) for anatomy and the release flow).
2. **Release** — pushing a tag `<name>/v<version>` runs
   [`release-plugin.yml`](.github/workflows/release-plugin.yml): validate →
   pack (manifest at archive root) → content-boundary check → cosign sign
   (keyless OIDC) → attach `<name>-<version>.tar.gz` + `.sha256` + `.sig` +
   `.pem` to a GitHub Release.
3. **Catalog** — the fermix repo ships a **static catalog**
   (`apps/fermix_core/priv/plugins/index.json`) inside the Fermix binary. It is
   regenerated by fermix's `scripts/release/sync_plugin_catalog.py`, which
   downloads and sha256- + cosign-verifies every artifact it pins. There is no
   remote index and no refresh: new plugins reach users with the next fermix
   release (`fermix upgrade`).
4. **Install** — when a user connects a plugin, the Fermix daemon downloads the
   tarball from the GitHub Release, re-verifies sha256 + cosign signature
   (identity-pinned to this repo's release workflow), enforces the content
   boundary, and installs it under `$FERMIX_HOME/plugins`.

## Validation

```sh
python3 scripts/validate_plugin.py --all          # every plugin dir
python3 scripts/validate_plugin.py plugins/<name> # one plugin
```

The same checks run in CI on every PR and again at release time before
signing.

## Contributing

All plugin changes land via PR → review → merge to `main`; releases are tags
on merged commits. The content of a plugin directory is strictly allowlisted
(`scripts/pluginlib.py`) — an artifact may contain only that plugin's
manifest, skills, assets, code, and vendored dependencies.
